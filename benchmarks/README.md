# Performance evidence

The initial gate used an Apple M2 Mac mini with eight cores and 8 GB RAM,
macOS 26.6 (25G72), Rust 1.91.0, and VSEARCH 2.31.0 for macOS arm64. Both
programs ran single-process with default thread behavior. Seven measured warm
runs followed one warm-up. `/usr/bin/time -lp` measured wall time and maximum
resident set size. Output was directed to `/dev/null`; separate full-output
SHA-256 checks proved byte equality for every fixture.

Fixtures were generated by `generate.rs` under
`/Volumes/Zane's HDD/rsomics-fixtures/metagenomics-0.1.0`. `derep-high` has
300,000 records and 10,000 unique sequences; `derep-low` has 300,000 unique
sequences; `prefix` has 100,000 records in nested families; `sort` has 500,000
records; `rereplicate` expands 50,000 amplicons to 1,000,000 records.

| Operation | rsomics median | VSEARCH median | Decision |
|---|---:|---:|---|
| full-length, high duplication | 0.26 s, 7.65 MB | 0.27 s, 7.44 MB | 1.04x throughput |
| full-length, all unique | 0.38 s, 145.11 MB | 0.54 s, 171.88 MB | 1.42x throughput and 15.6% less RSS |
| prefix dereplication | 0.18 s, 68.83 MB | 0.23 s, 35.57 MB | 1.28x throughput; memory regression retained as an explicit optimization target |
| abundance sort | 0.43 s, 172.57 MB | 0.58 s, 103.09 MB | 1.35x throughput; memory regression retained as an explicit optimization target |
| rereplication | 0.03 s, 19.51 MB | 0.30 s, 1.93 MB | 10.0x throughput; the higher RSS pays for preflight expansion validation |

The release gate is a throughput win on every operation and a throughput plus
memory win on low-duplication full-length dereplication. Prefix and sort still
buffer owned records because their result needs global ordering; their RSS is
reported rather than hidden.
